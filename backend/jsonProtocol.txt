Definitions for all JSON messages sent between Frontend and Backend and fields they include

Each JSON message starts with a 'type' field defining the purpose of the request/message
For example, a request to create a room would have 'type' : 'create-room' 

Frontend -> Backend:
    Request: create-room
        playerId
        difficulty
        capacity
        codingTime
        votingTime
        turnDuration (30 or 60, seconds per turn)
    Response: room-created
        roomId
        playerId
        difficulty
        capacity
        codingTime
        votingTime
        turnDuration
        hostId

    Request: join-room
        roomId
        playerId
    Response: room-joined
        roomId
        playerId
        difficulty
        capacity
        codingTime
        votingTime
        turnDuration
        playerList
        hostId
    Response: unable-to-join
        errorMessage

    Message: leave
        roomId
        playerId

    Request: start-game
        roomId
    Response: game-started
        playerList
        imposterId
        chat
        problem
        tests

    Request: set-ready
        roomId
        playerId
    Response: player-ready
        readyCount

    Request: send-message:
        roomId
        playerId
        message
        timestamp

    Request: new-code
        roomId
        code
    Response: new-code
        code

    Request: run-tests
        roomId
        playerId
        code 
    Response: test-results
        error
        outputList
        passedList

    Request: next-turn
        roomId
        playerId
        code
    Response: next-turn
        playerId
        code

    Request: cast-vote
        roomId
        voterId
        votedId
    Response: vote-casted
        votes

    Request: play-again
        roomId
        playerId
        (adds the player to the rematch ready set; valid only during RESULTS)

    Request: lobby-player-pos
        roomId
        playerId
        x
        y
        score
        (throttled position update sent ≤20/s while on lobby page; ignored if game in progress)

    Request: lobby-goal-reached
        roomId
        playerId
        goalVersion
        (sent when local player collides with goal; server validates goalVersion to prevent double-moves)

Backend -> Frontend
    Message: room-players-update
        playerList
        hostId

    Message: game-players-update
        playerList
        playerId

    Message: chat-update
        chat

    Message: briefing-time-left
        briefingTimeLeft

    Message briefing-over

    Message: coding-time-left
        codingTimeLeft
        turnTimeLeft

    Message: turn-over

    Message: coding-over
        commits
        votes

    Message: voting-time-left
        votingTimeLeft

    Message: voting-over
        votedList
        votedCorrectly

    Message: rematch-time-left
        rematchTimeLeft

    Message: rematch-update
        playerList
        readyList
        hostId
        (broadcast when a player opts into a rematch or leaves during RESULTS)

    Message: rematch-over
        playerList
        hostId
        (rematch window closed: non-ready players pruned, game reset, host may start)

    Message: game-sync (reply to sync-game-state; also sent on visibilitychange)
        gameState
        briefingTimeLeft
        codingTimeLeft
        turnTimeLeft
        turnDuration
        votingTimeLeft
        playerList
        playerId
        cursor
        rematchTimeLeft
        readyList
        hostId

    Message: lobby-player-pos
        playerId
        x
        y
        score
        (relayed to all room members except sender; only while game not started)

    Message: lobby-goal-update
        x
        y
        goalVersion
        (broadcast to all room members when goal moves; also sent directly to a joining player)

    Message: imposter-disconnected

    Message: not-enough-players

Other:
    Request: get-health
    Response:
        roomList
